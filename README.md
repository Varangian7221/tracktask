# TaskFlow — учебный MVP трекера задач

Веб-приложение для одного пользователя: список задач с созданием, редактированием, удалением, статусами, приоритетами, поиском, фильтрами, сортировкой и сводкой. Учебный проект по мотивам архивного заказа FL.ru «Разработка трекера задач» (10.09.2020); исходное ТЗ и макеты Figma заказчика публично не раскрыты, поэтому реализована минимальная спецификация из файла `ТЗ_Кейс_4_Трекер_задач.md`. Оформление выполнено по учебному брендбуку «TaskFlow — Modern Productivity»; название TaskFlow предварительное.

## Реализованные функции (по ТЗ)

- Просмотр списка задач с понятным пустым состоянием (FR-01).
- Создание задачи: обязательное название (проверка после удаления пробелов), необязательные описание, срок и приоритет; по умолчанию приоритет «Средний», статус «К выполнению» (FR-02, FR-04, FR-05).
- Редактирование всех полей задачи, включая статус; изменения отображаются сразу (FR-03).
- Ровно три статуса («К выполнению», «В работе», «Выполнена») и три приоритета («Низкий», «Средний», «Высокий») с едиными обозначениями по всему приложению (FR-04, FR-05).
- Удаление с подтверждением; после подтверждения задача удаляется из списка и хранилища (FR-06).
- Поиск по части названия без учёта регистра; данные при поиске не изменяются (FR-07).
- Фильтры по статусу и приоритету (работают совместно) с кнопкой сброса (FR-08).
- Сортировка по дате создания и по сроку выполнения; задачи без срока выводятся после задач со сроком в обоих направлениях (FR-09).
- Сводка: всего задач, незавершённых, выполненных — обновляется после изменений (FR-10).
- Сохранение данных в localStorage; повреждённые данные не приводят к падению приложения (FR-11).
- Сообщения об успехе и понятные ошибки; при ошибке валидации введённые данные не теряются (FR-12).
- Состояния интерфейса: загрузка, пустой список, «Ничего не найдено», ошибка загрузки/сохранения (раздел 6 ТЗ).
- Адаптивная вёрстка: одноколоночный макет на узких экранах (от 360 px), двухколоночный от 600 px, пять колонок управления от 900 px.

Не входит в MVP (по разделу 2 ТЗ): регистрация/авторизация, совместная работа, уведомления, оплата, production-размещение, воспроизведение недоступных макетов Figma.

## Стек

- **Frontend:** React 18 + TypeScript, сборка Vite 6.
- **Стилизация:** обычный CSS (CSS-переменные, медиа-запросы), без CSS-фреймворков.
- **Тесты:** Vitest 3 + jsdom (юнит-тесты фильтрации, сортировки, валидации и слоя хранения).
- **Линт:** ESLint 9 (typescript-eslint, react-hooks, react-refresh).

## Дизайн-система (брендбук TaskFlow)

Учебный брендбук «TaskFlow — Modern Productivity»; макетов Figma нет, поэтому используется собственная дизайн-система, рабочее название TaskFlow предварительное.

- **Палитра:** основной индиго `#4338CA`, фон `#F8FAFC`, белые карточки `#FFFFFF`, основной текст `#0F172A`.
- **Статусы:** «К выполнению» — серый, «В работе» — синий, «Выполнена» — зелёный.
- **Приоритеты:** «Низкий» — серый, «Средний» — янтарный, «Высокий» — красный.
- **Типографика:** Inter (подключается с Google Fonts) с откатом на системный sans-serif.
- **Геометрия:** скругления 8/10/12 px, отступы кратны 8 px.
- **Иконки:** собственные линейные SVG-иконки единого стиля (`src/components/Icons.tsx`).
- **Адаптив:** одна колонка до 600 px, две колонки управления до 900 px, четыре колонки + строка действий на десктопе.

## Хранение данных и его ограничения

Задачи хранятся в **localStorage** браузера под ключом `taskflow.tasks.v1` (массив задач в формате JSON). Данные привязаны к браузеру и origin: они переживают перезагрузку страницы и перезапуск приложения, но:

- не синхронизируются между устройствами и браузерами;
- исчезают при очистке данных браузера / использовании приватного окна с автОчисткой;
- квота localStorage (~5 МБ) ограничивает общее количество задач;
- при повреждении данных приложение не падает: показывается сообщение об ошибке, список начинается пустым (восстановить испорченные данные нельзя — резервных копий нет).

Хранение вынесено в отдельный слой `src/storage/taskStorage.ts`, поэтому при желании его можно заменить на API-бэкенд без переделки UI.

## Структура проекта

```
src/
  types/task.ts            # модель задачи, статусы, приоритеты, подписи
  storage/taskStorage.ts   # чтение/запись localStorage с валидацией
  utils/taskUtils.ts       # id, даты, валидация названия
  utils/taskFilters.ts     # фильтрация и сортировка (чистые функции)
  components/              # UI: TaskCard, TaskList, TaskForm, TaskControls,
                           # Summary, ConfirmDialog, MessageBanner, Icons
  App.tsx                  # состояние приложения и связь UI с хранилищем
  index.css                # дизайн-система TaskFlow, включая адаптивные брейкпоинты
```

## Деплой

Приложение размещено на Cloudflare Workers (статические ассеты, ранее — Cloudflare Pages):

- **Продакшн:** https://tracktask.varangian7221.workers.dev
- **Конфигурация:** `wrangler.jsonc` (+ плагин `@cloudflare/vite-plugin` в `vite.config.ts`)
- **Публикация новой версии:** `npm run deploy` (после `npx wrangler login` при первой авторизации)

Приложение полностью статическое: серверная логика не используется, данные хранятся в localStorage браузера посетителя.

## Известные ограничения и не реализованные функции

- Нет бэкенда, базы данных и синхронизации: хранение только в localStorage (допустимо по разделу 7 ТЗ для локального однопользовательского MVP).
- Нет пагинации: при очень большом числе задач список отображается целиком.
- Нет drag-and-drop и быстрой смены статуса из карточки — статус меняется только через форму редактирования.
- Нет экспорта/импорта данных.
- Редактирование даты в поле `<input type="date">` зависит от локали и нативного date-пикера браузера.
- Автотестами покрыта только логика (фильтры, сортировка, валидация, хранение); UI-компоненты проверялись вручную в браузере.
- Визуальная проверка на физической ширине 360 px выполнялась по CSS-брейкпоинтам и логической вёрстке (без эмуляции устройства в тестовой среде).
